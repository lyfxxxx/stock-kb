# 人工 rubric：扫描稿发布门

审核人：用户。  
本清单**挡发布、不挡** `python tools/run_eval_regression.py`。自动回归仍只看 G1–G11（组稿引用页含该数、检索/结构化门槛）。文笔是否像 modest_ 也只走本清单，不设 LLM judge。

两家试点（海底捞、百胜中国）都要过关才算可发布：

| # | 检查 | 过关 |
|---|---|---|
| R1 | 骨架齐全（2026-09-12 新模版） | 公司简介/股权管理层 → 利润表 → 分业务 → 资产负债（逐科目小标题，金额进标题）→ 现金流（累计五件套）→ 分红 → 行业与同行 → 未来看点 → 总结收束 → 附引用明细；☆节可按需取舍并明说，总判断与估值只在总结 |
| R2 | 判断已标注 | 看点、风险、口吻带「判断」；财务表单元格不是判断；判断自然分布在节内（每节 0–2 处，有观点才写） |
| R3 | 无表外无出处数字 | 每个关键数字带注释号 [n]，文末「附：注释」逐条可查 `《文件》第N页`；判断段引用上文已出处的事实可不再带号 |
| R4 | HTML 有图 | 至少一张 `<svg`（或等价图表）；利润 / 资产负债 / 现金流至少覆盖库内序列 |
| R5 | 估值可复核 | 总结含 PE_TTM = 最新市值 / TTM 归母净利；写明价格日期、上市币种、实时汇率来源；先财报币种再人民币 |
| R6 | 行情失败则无成稿 | 无市价、无市值、无汇率时整篇失败，不写半成品、不编 PE |
| R7 | 数据不写回生产库 | 行情、股东穿透、分产品抽取不写入 `stock_kb.db` |
| R8 | 单位口径统一 | 图表与正文用亿/亿美元等人读口径并标注单位；出处表保留原值 + 单位列；无「43.2M 千元」这类歧义缩写 |
| R9 | 出处注释式 | 正文与表格不出现《文件》页码；出处统一放文末「附：注释（数据出处）」，正文数字用可点击的 [n] 上标跳转；图 caption 为一句话 |
| R10 | 图例与序列一致 | 无「有图例无数据」的幻影系列；空序列不进图例；坐标轴带单位 |
| R11 | 趋势与收束（新模版） | 收入/归母有带出处的趋势句；资产负债净现金带公式与打折检查；现金流含累计五件套（注明按表内原值累计）与 FCF/净利润比值；现场心算 ≥2 处；总结为「生意质量 + PE×派息率→股息率（含情景）+ 风险」；正文无写作指令或过程性文字 |

样张路径：`eval/generated_notes/<公司>/<日期>-<公司>-扫描.html`。  
组稿底稿（`compose-note`）可以没有判断和 PE；正式稿是 skill 扫描 HTML。
