较复杂问题的混合检索流程详解

本文逐步说明「较复杂问题」在 stock-kb 中的混合检索过程。配套流程图见下方嵌入，也可直接打开 hybrid-retrieval-complex.html 查看。

1. 复杂问题

示例问题：

百胜中国 2024 年经营现金流能否覆盖资本开支？

这类问题同时包含：

  • 公司：百胜中国；
  • 年份：2024 年；
  • 关键词：经营现金流、资本开支；
  • 语义判断：能否覆盖，是一个比较/判断关系，不是单纯的字面命中。

当前 hybrid_search 不会自动把问题拆成子问题，而是把整句作为一次查询；company 作为参数传入，用于限定公司范围。

2. 查询规范化

索引侧已经做过繁体转简体（opencc t2s），所以入库的 pages.content 是简体文本。查询侧目前主要是 strip 去掉首尾空白后直接做 embedding，尚未做同义改写或子问题拆分；这两项属于理想步骤，后续再补。

3. FTS5 关键词检索

关键词路由规则：

  • 查询长度 >= 3：使用 pages_fts MATCH，走 trigram 分词，查询词被包成短语（双引号转义后按短语匹配）；
  • 查询长度 < 3：使用 LIKE，带 ESCAPE 兜底；
  • 两种路径都支持 company 过滤。

以公司为「百胜中国」、关键词为「资本开支」为例，FTS 命中的候选页包括：

  • 华源证券研报 第 1 页；
  • 百胜中国_招股书_中文版 第 332 页；
  • 百胜中国_招股书_中文版 第 302 页。

这些页面内容分别涉及资本开支。

4. 向量语义检索

向量侧默认模型为 BAAI/bge-small-zh-v1.5，维度为 512。sqlite-vec 先取 top_k * 5 个候选块（chunks），再按 page_id 去重（同一页保留距离最近的块），同时支持 company 过滤。

示例：vector 命中百胜中国_招股书_中文版 第 219 页、第 220 页，内容涉及现金流量和流动资金与资本资源。

5. 混合排序与去重

当前实现是：先取 FTS 的 top_k，再取向量的 top_k；按 page_id 去重后，FTS 优先、向量补位，交替填充到 top_k。这里不是 RRF 加权融合。

实际效果：复杂自然语言问题下 FTS 可能为空，最终以向量结果为主；若问题里带有精确词（如「资本开支」），则 FTS 命中会排在前，向量再补位。

6. 返回 top_k

返回结果包含以下字段：

字段含义
page_id页面唯一 ID
page_no页码
report_id报告 ID
company公司名
title报告标题
path报告文件路径
score排序分数（向量命中为距离，越小越近）
source来源：fts 或 vector
snippet命中片段，用于取原文和生成引用

source 表示命中来自 FTS 还是向量；snippet 提供命中位置附近的文本，供后续 agent 取原文并生成可追溯引用。

7. 一个完整例子串联

仍以「百胜中国 2024 年经营现金流能否覆盖资本开支？」为例：

  1. FTS 对整句做 trigram 短语匹配，可能返回空（整句没有精确词面命中）；
  2. 向量检索做语义召回，补充「现金流量」「流动资金与资本资源」等相关候选页；
  3. 混合排序按 FTS 优先、向量补位，返回候选 top_k；
  4. 后续 agent 读取这些页面的原文，定位经营现金流与资本开支的具体数字，并生成引用。
